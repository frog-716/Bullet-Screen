# 已知限制与维护交接

这是后续维护者开始工作前应先读的边界清单。下列项目是当前已接受的限制或尚未验证的事项，不等于都已发生故障。

稳定基线：`bullet-screen-v1-final`，`acd9d5a21e8955f1d9939940391213e2b38756b5`。

状态说明：`P2` 表示有实际边界，但目前不阻止本机使用；`P3` 表示主要增加维护成本；`UNKNOWN` 表示证据不足，不能据此承诺能力。

## 1. Douyin 部分房间兼容性有限

- 当前状态：P2（能力有限，已接受）
- 用户影响：有些页面能打开，但互动数据仍可能不可用。
- 为什么现在接受：页面状态与互动读取状态分开显示；真实页面表现会因房间和页面状态不同。
- 什么时候值得重新打开：官方接口或新的受支持方式经过合成测试和真实公开页面验证后。
- 当前绕过办法：确认直播仍在播、检查登录状态、重新连接、换公开房间；先用 Demo 检查本机安装。
- 相关模块：`douyin/douyin_adapter.py`、`douyin/server.py`、`douyin/app.js`。

## 2. Douyin binary WebSocket 不是正式事件通道

- 当前状态：UNKNOWN（明确不承诺）
- 用户影响：部分互动可能不会通过当前正式 HTTP 主路径进入事件列表。
- 为什么现在接受：未知 binary frame 不会冒充标准事件，也不会刷新采集可靠时间；当前产品不宣称支持该通道。
- 什么时候值得重新打开：取得可公开、安全、可脱敏复现的协议证据，并能建立不含真实 payload 的 fixture。
- 当前绕过办法：使用已验证能返回互动的公开房间；若互动不可用，查看页面状态或运行 Demo。
- 相关模块：`douyin/douyin_adapter.py`、`douyin/server.py`。

## 3. 真实 v2 → v4 历史库升级尚未验收

- 当前状态：UNKNOWN（真实数据未验证）
- 用户影响：旧 v2/v3 数据库会被当前服务拒绝写入；不能保证整条真实升级链安全。
- 为什么现在接受：服务 fail closed 并保留旧文件，不会悄悄改库；迁移只在隔离 fixture/副本中验证。
- 什么时候值得重新打开：先有独立备份、代表性副本和逐项数据语义核对，再单独批准真实升级。
- 当前绕过办法：先用 Demo，或显式配置一个新的 v4 数据库；不要删除、改名或覆盖旧库。
- 相关模块：`scripts/govern_databases.py`、`bilibili/server.py`、`douyin/server.py`、`docs/DATA.md`。

## 4. 突然断电后的恢复未做物理断电验证

- 当前状态：UNKNOWN（代码顺序有测试，实机断电未测）
- 用户影响：不能把模拟中断测试等同于真实断电、磁盘故障或硬件写缓存验证。
- 为什么现在接受：迁移和恢复有临时副本、日志、验证与恢复测试；没有对真实用户数据做危险的断电实验。
- 什么时候值得重新打开：准备专用临时设备、可恢复镜像和断电演练方案时。
- 当前绕过办法：重要操作前使用项目备份工具；迁移前另存独立副本。
- 相关模块：`scripts/govern_databases.py`、`scripts/data_lifecycle.py`、`tests/`。

## 5. 未在另一台全新物理 Mac 完整验收

- 当前状态：UNKNOWN（本机干净目录演练不等于另一台实体机器）
- 用户影响：不同 macOS、芯片、权限和系统工具组合仍可能暴露安装差异。
- 为什么现在接受：本机安装、环境检查和构建路线已有自动化演练；本任务没有第二台 Mac 可验证。
- 什么时候值得重新打开：准备对外分发或支持新的 Mac/macOS 组合前。
- 当前绕过办法：按 README 执行 setup、doctor、build 和 smoke test；失败时保留具体错误输出。
- 相关模块：`scripts/setup.sh`、`scripts/doctor.py`、`macos/build-app.sh`、`README.md`。

## 6. App 不是 Developer ID 签名，也未公证

- 当前状态：P2（本机开发/试用可接受，不代表公开发行）
- 用户影响：macOS 可能显示安全确认或阻止直接打开。
- 为什么现在接受：当前交付目标是本机运行，构建使用 ad-hoc signing；没有把它描述成正式发行包。
- 什么时候值得重新打开：决定向不熟悉终端的用户公开分发时。
- 当前绕过办法：只从可信项目目录构建；按 README 的 macOS 安全提示处理，不要下载来历不明的替代 App。
- 相关模块：`macos/build-app.sh`、`README.md`。

## 7. 长会话性能拐点未知

- 当前状态：UNKNOWN（未做长时间容量基准）
- 用户影响：事件和指标越积越多时，查询与界面更新时间可能变慢；目前没有证据确定何时发生。
- 为什么现在接受：常见本机单用户使用有时间窗和列表限制；没有 8 小时或更长的代表性基准数据。
- 什么时候值得重新打开：用户报告看板明显变慢，或计划把单次会话用于长时间归档时。
- 当前绕过办法：先用较短会话；变慢时记录持续时间、数据库大小和页面表现，再决定是否需要容量优化。
- 相关模块：`bilibili/server.py`、`douyin/server.py`、两份 Dashboard。

## 8. Launcher 遇到极端 SIGTERM 超时不会自动强杀

- 当前状态：P2（异常退出路径，已接受）
- 用户影响：若服务进程忽略正常停止请求，Launcher 会保持“正在停止/停止超时”，而不是谎称已停止。
- 为什么现在接受：默认不发送强制 kill，避免误伤或丢失仍在写入的数据；没有证据表明正常停止经常触发此路径。
- 什么时候值得重新打开：确认受支持环境中正常使用频繁卡在停止，或能明确界定安全的第二阶段终止策略时。
- 当前绕过办法：等待状态更新；若持续不退出，先退出当前操作并使用 macOS 活动监视器检查由 Bullet-Screen 启动的进程，不要随意结束其他浏览器。
- 相关模块：`macos/BulletScreenLauncher.swift`、`macos/LauncherLifecycle.swift`。

## 9. 异常中断会话的历史覆盖边界

- 当前状态：UNKNOWN（有恢复处理，历史连续性不能由此证明）
- 用户影响：电脑或服务意外退出后，已有事件和指标仍可保留，但不能把没有记录的时间当作可靠采集。
- 为什么现在接受：启动时会标记中断会话，统计窗口依据实际会话、事件、快照和缺口判断；未记录的区间无法补成真实证据。
- 什么时候值得重新打开：发现中断窗口被显示为完整可靠，或需要对历史中断区间给出更细的覆盖保证时。
- 当前绕过办法：查看窗口覆盖说明；`unknown` 或 `gap` 不要解释成“没有互动”。
- 相关模块：`bilibili/server.py`、`douyin/server.py`、`douyin/live_intelligence.py`。

## 10. Bilibili 长期重放/重连去重没有全局保证

- 当前状态：P2（事件重复风险，已接受）
- 用户影响：平台重放或重新推送的相同互动，在特定情况下可能让事件计数偏高。
- 为什么现在接受：当前持久事件逐条写入，没有跨长会话的上游事件全局唯一约束；修改去重可能误合并同秒同内容的不同用户事件。
- 什么时候值得重新打开：有可脱敏重现的真实重复证据，并能用平台 ID 与冲突 fixture 证明不会漏计。
- 当前绕过办法：把事件数理解为当前采集到的记录数，不作审计或结算用途；遇到明显重复先记录房间、时间和事件类型。
- 相关模块：`bilibili/server.py`、`douyin/server.py` 中的 Bilibili 兼容实现。

## 11. 本机 HTTP 服务没有应用层并发上限

- 当前状态：UNKNOWN（容量未测）
- 用户影响：多个页面或其他本机客户端同时高频请求时，资源占用上限没有量化。
- 为什么现在接受：服务绑定本机回环地址，典型用法是单个本机 Dashboard；目前没有测得容量拐点。
- 什么时候值得重新打开：支持多个并发看板/客户端，或观察到请求堆积、线程或资源持续增长时。
- 当前绕过办法：通常只打开一个看板；不要配置成局域网或公网服务。
- 相关模块：`bilibili/server.py`、`douyin/server.py`。

## 12. build-app 可能先删除旧 App 再构建

- 当前状态：P2（已由当前脚本确认）
- 用户影响：`build-app.sh` 在编译前会移除 `dist/Bullet-Screen.app`；如果后续构建失败，旧构建产物也可能已经不在原位置。
- 为什么现在接受：源码不会因此丢失，App 可重新构建；当前任务不改变构建流程，也不会覆盖现有产物。
- 什么时候值得重新打开：开始面向普通用户发布，或要求构建失败时仍保留可运行旧 App 时。
- 当前绕过办法：重建前把现有 App 复制到项目外安全位置；确认 Swift 和项目 Python 可用后再构建。
- 相关模块：`macos/build-app.sh`。

## 13. Brotli 极端压缩输入边界未穷尽验证

- 当前状态：UNKNOWN（已有大小和解压预算，极端组合未穷举）
- 用户影响：超大或异常嵌套数据可能被拒绝；不同有效响应形态也可能因预算限制而无法解码。
- 为什么现在接受：解析器设置了原始/解压大小、包数和嵌套深度限制；没有证据表明正常公开房间因这些限制普遍失败。
- 什么时候值得重新打开：出现脱敏的合法响应因明确预算边界而被拒，或资源使用超出预期时。
- 当前绕过办法：保留默认预算，不要为单个 payload 去掉限制；用合成数据重现并评估安全上限。
- 相关模块：`bilibili/server.py`、`douyin/server.py`、`douyin/douyin_adapter.py`。

## 14. Bilibili Cookie 的 WebSocket 目标主机没有独立静态白名单

- 当前状态：P2（目标来源依赖平台返回的主机列表）
- 用户影响：连接使用的 Cookie 会随请求发送到采集配置所给出的 WebSocket 主机；当前代码不另设固定主机白名单。
- 为什么现在接受：主机列表由 Bilibili 登录/房间流程返回，当前用途是连接平台互动服务；不向浏览器页面公开 Cookie，也不把它写入事件库。
- 什么时候值得重新打开：平台主机来源变化、发现非平台目标可能被接受，或准备让不可信输入控制该主机时。
- 当前绕过办法：只输入可信 Bilibili 直播间；仅在确有需要时提供 Cookie，不要把 Cookie 交给第三方或未知工具。
- 相关模块：`bilibili/server.py`、`douyin/server.py` 中的 Bilibili 兼容实现。

## 15. 双 Bilibili 服务实现重复维护

- 当前状态：P2（维护成本，已接受）
- 用户影响：修复可能需要同时更新正式 Bilibili 服务和 Douyin 的兼容入口，否则行为可能逐渐不同。
- 为什么现在接受：当前仍有双入口契约测试；大规模合并会扩大变更面，不能只为减少重复代码而进行。
- 什么时候值得重新打开：重复修改持续造成缺陷，或后续明确设计并验证一个最小共享边界时。
- 当前绕过办法：涉及共享协议/数据契约时同时运行两入口测试。
- 相关模块：`bilibili/server.py`、`douyin/server.py`、`tests/`。

## 16. 长期安全维护规则分散且较薄

- 当前状态：P3（维护流程风险，已接受）
- 用户影响：新维护者若只看很短的 `AGENTS.md`，可能看不到所有数据保护和验收约定。
- 为什么现在接受：当前根 `AGENTS.md` 主要指向本地工单、分诊和领域文档规则；用户数据边界另有 `docs/DATA.md`，本文件补充已接受限制，但并没有把所有审查历史搬进 README。
- 什么时候值得重新打开：新增维护者或外部贡献流程时，若出现漏读约束或重复确认成本明显增加。
- 当前绕过办法：开始改代码前读本文件及相关 README、`docs/DATA.md` 和测试；所有数据库/Profile 操作仍需按明确任务授权执行。
- 相关模块：`AGENTS.md`、`docs/DATA.md`、`docs/agents/`、`README.md`。

## 17. 200% 页面缩放下看板需要横向浏览

- 当前状态：P2（高缩放布局边界，已接受）
- 用户影响：教程窗口可以滚动并通过键盘操作，但两栏看板不能同时显示在较窄的有效视口内，部分区域需要横向浏览。
- 为什么现在接受：本批确认普通窗口尺寸可用，并确认教程本身在 200% 缩放下仍可操作；重排整套看板布局超出本批范围。
- 什么时候值得重新打开：改善高缩放/窄窗口可读性，或作为无障碍与公开发行验收要求时。
- 当前绕过办法：临时降低页面缩放，或使用更宽的窗口；教程内容可在弹窗内滚动并用键盘到达底部操作。
- 相关模块：`bilibili/styles.css`、`douyin/styles.css`、两个 Dashboard 的教程弹窗标记。

本清单不是许可去试验真实用户数据库、登录 Profile 或未承诺的平台通道。若证据改变，先针对隔离副本/合成输入建立复现，再决定是否重开对应项目。
